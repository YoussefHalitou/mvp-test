
Application Overview: "Land in Sicht" - Project Management System
This is a comprehensive German-language project management and logistics platform for a moving and relocation services company. The workflow spans multiple stages from initial planning to final cost calculation.

Main Workflow Phases
Phase 1: Pre-Planning (Prä - MorningPlan / Kalender - page7)
Purpose: Schedule and prepare upcoming projects
Key Activities:
1. Project Creation & Management
    * Create new projects with customer details (name, address, contact)
    * Assign service types (Umzug/Moving, Entrümpelung/Clearance, Transport)
    * Set project dates (single-day or multi-day projects)
    * Store project times and notes
2. Customer Integration
    * Integration with Lexware accounting system
    * Load and sync customer contacts from Lexware API
    * Create new Lexware contacts directly from projects
    * Maintain customer database for billing
3. Visual Planning
    * Calendar view showing all scheduled projects
    * Filter projects by date range
    * Color-coded by service type (green for moves, yellow for clearances)
Data Flow:
* Projects stored in t_projects table
* Calendar events generated from project dates
* Multi-day projects automatically expanded into daily entries
* Lexware contacts cached in t_lexware_contacts_full

Phase 2: Daily Planning (Inter - MorningPlan - page8)
Purpose: Create detailed daily work plans and team assignments
Key Activities:
1. Daily Plan Creation
    * View all projects scheduled for selected date
    * Create "plans" (Einsätze) linking projects to vehicles and teams
    * Assign start times, vehicles (L4U, L4N, L Khalid, L Caddy, L Olaf, L Star)
    * Add plan-specific notes
2. Team Assignment
    * For each plan, assign team members from employee catalog
    * Employees categorized as "Intern" or "Frei/Khalid" (freelance)
    * Set individual start times per team member
    * Add member-specific notes
3. Vehicle Management
    * Track daily vehicle status for 6 vehicles
    * Record vehicle information and availability
    * Reorderable vehicle list with custom daily sorting
    * Persist vehicle order preferences per date
4. Employee Notes System
    * Separate note sections for internal and external employees
    * Daily notes linked to employees and dates
    * Reorderable note lists with drag-and-drop
    * Notes stored in t_employee_daily_notes
5. Morning Plan Export
    * Generate comprehensive HTML/PDF morning plan
    * Includes all cards (projects), teams, vehicles, and employee notes
    * Uses templating system to format data for printing/distribution
Data Flow:
* Plans stored in t_morningplan table (plan_id → project_id → vehicle → notes)
* Team assignments in t_morningplan_staff (staff linked to plan_id)
* Vehicle status in t_vehicle_daily_status (one row per vehicle per day)
* Employee notes in t_employee_daily_notes (linked to employee_code + date)

Phase 3: Post-Planning / Completion (Post - MorningPlan - page11)
Purpose: Record actual work performed and time tracking
Key Activities:
1. Time Pair Recording
    * For each team member on each project, record time pairs:
        * LiS times (Land in Sicht company times): When employee worked
        * Customer times: Billable time at customer location
        * Break minutes
    * Calculate total hours (LiS vs. Customer hours)
    * Time pairs automatically created based on morning plan staff assignments
2. Work Assignments Management
    * Create standalone work assignments (work not tied to specific projects)
    * Track work types, employees, dates, times, hours
    * Used for administrative work, maintenance, or non-project tasks
3. Project Cards Display
    * Similar card-based view as inter-morning plan
    * Shows completed projects with their teams
    * Editable time entries for each team member
Data Flow:
* Time pairs stored in t_time_pairs table
    * Linked by project_id and mitarbeiter (employee name)
    * Contains lis_von, lis_bis, kunde_von, kunde_bis, pause_min
    * Calculated fields: ges_lis_h, ges_kd_h (total hours)
* Work assignments in t_work_assignments (separate from projects)

Phase 4: Cost Calculation (Nachkalkulation - Nachkalkulation page)
Purpose: Calculate actual project costs vs. revenue
Key Activities:
1. Project Selection
    * Select a completed project for cost analysis
    * View project details and customer information
2. Cost Categories
    * Personnel Costs (Personal): Employee time × hourly rates from time pairs
    * Material Costs (Material): Materials used on project from material catalog
    * Vehicle Costs (Fahrzeuge): Vehicle usage costs
    * Service Costs (Services): External services contracted for project
    * Other Costs (Kosten): Miscellaneous expenses
3. Revenue Tracking
    * Revenue Items (Erlöse): Line items billed to customer
    * Can be based on service catalog or custom items
4. Financial Calculations
    * Total costs aggregation across all categories
    * Total revenue calculation
    * Margin calculation: Marge = Revenue - Costs
    * Margin percentage: (Revenue - Costs) / Revenue × 100%
    * Generate financial report/calculation document
Data Flow:
* Project costs pulled from multiple sources:
    * Time pairs → personnel costs
    * t_project_materials → material costs
    * t_project_vehicle_costs → vehicle costs
    * t_project_service_usage → service costs
* Revenue from t_project_revenue_items
* Calculations performed by transformers (tr_kosten_gesamt_total, tr_erloes_gesamt_total, tr_marge_euro, tr_marge_prozent)

Supporting Catalogs
1. Employee Catalog (Mitarbeiterkatalog)
* Manage employee master data
* Employee codes, names, contract types (Intern/Frei)
* Hourly rates, roles, active status
* Used for team assignments and cost calculations
2. Material Catalog (Materialkatalog)
* Materials and supplies inventory
* Material costs, pricing
* Link materials to projects for cost tracking
3. Service Catalog (Leistungskatalog)
* Services offered by company
* Service prices from different suppliers
* Used for project planning and revenue items

Key Technical Patterns
1. Date-Based Filtering: Most pages filter by selected date
2. Automatic Queries: Many queries run automatically on date changes
3. Manual Saves: Changes require explicit save actions (buttons)
4. State Management: Extensive use of State variables for caching data per date
5. Transformer Calculations: Real-time calculations using transformers
6. Modal Workflows: Forms in modals/drawers for creating/editing records
7. Reorderable Lists: Drag-and-drop functionality for notes and vehicles
8. Bulk Operations: Bulk insert/update operations for time pairs and vehicle status

Data Integration Points
* Lexware API: Customer contact synchronization
* PDF Generation: Morning plan and calculation reports via external service
* PostgreSQL: Main data storage across multiple related tables
* Relational Links: Projects → Plans → Teams → Time Pairs → Cost Calculation
This workflow enables the company to manage the complete lifecycle of moving/logistics projects from initial customer contact through execution to final financial analysis.

Cost & Revenue Calculations (Transformers)
Personnel Costs Total
* Transformer: tr_personal_kosten_gesamt → lib/tr_personal_kosten_gesamt.js
* Input: Q_time_pairs_with_rates.data
* Calculation: SUM(kosten) = SUM(lis_stunden × hourly_rate)
Material Costs Total
* Transformer: tr_material_kosten_gesamt → lib/tr_material_kosten_gesamt.js
* Input: Q_project_materials.data
* Calculation: SUM(total_cost) = SUM(quantity × cost_per_unit)
Material Revenue Total
* Transformer: tr_material_erloes_gesamt → lib/tr_material_erloes_gesamt.js
* Input: Q_project_materials.data
* Calculation: SUM(total_price) = SUM(quantity × price_per_unit)
Vehicle Costs Total
* Transformer: tr_vehicle_kosten_gesamt → lib/tr_vehicle_kosten_gesamt.js
* Input: Q_project_vehicle_costs.data
* Calculation: SUM(total_cost)
Service Costs Total
* Transformer: tr_service_kosten_gesamt → lib/tr_service_kosten_gesamt.js
* Input: Q_project_service_costs.data
* Calculation: SUM(cost)
Inspection Revenue Total
* Transformer: tr_erloes_gesamt → lib/tr_erloes_gesamt.js
* Input: Q_inspection_calc_items_for_erloes.data
* Calculation: SUM(line_total) from inspection items
Revenue Items Total
* Transformer: tr_revenue_items_gesamt → lib/tr_revenue_items_gesamt.js
* Input: Q_project_revenue_items.data
* Calculation: SUM(line_total)
Total Costs
* Transformer: tr_kosten_gesamt_total → lib/tr_kosten_gesamt_total.js
* Formula: personalKosten + materialKosten + vehicleKosten + serviceKosten
* Inputs:
    * tr_personal_kosten_gesamt.value
    * tr_material_kosten_gesamt.value
    * tr_vehicle_kosten_gesamt.value
    * tr_service_kosten_gesamt.value
Total Revenue
* Transformer: tr_erloes_gesamt_total → lib/tr_erloes_gesamt_total.js
* Formula: inspectionErloes + materialErloes + revenueItemsErloes
* Inputs:
    * tr_erloes_gesamt.value
    * tr_material_erloes_gesamt.value
    * tr_revenue_items_gesamt.value
Margin (Euro)
* Transformer: tr_marge_euro → lib/tr_marge_euro.js
* Formula: Revenue - Costs
* Inputs:
    * tr_erloes_gesamt_total.value
    * tr_kosten_gesamt_total.value
Margin (Percentage)
* Transformer: tr_marge_prozent → lib/tr_marge_prozent.js
* Formula: (Revenue - Costs) / Revenue
* Inputs:
    * tr_erloes_gesamt_total.value
    * tr_kosten_gesamt_total.value
* Returns: Decimal (e.g., 0.4893 for 48.93%)
* Note: UI component multiplies by 100 for display

Data Flow Summary
PROJECT LIFECYCLE:

1. PRE-PLANNING (page7)
   ├─ Create t_projects → project_id
   ├─ Sync lexware_contacts_full ← Lexware API
   └─ View calendar (Q_projects_calendar)

2. DAILY PLANNING (page8)
   ├─ Create t_morningplan → plan_id (links project_id)
   ├─ Assign t_morningplan_staff (links plan_id + employee_id)
   ├─ Set t_vehicle_daily_status (per plan_date)
   ├─ Add t_employee_daily_notes (per employee + date)
   ├─ Auto-create t_time_pairs skeleton (via Q_create_time_pairs_for_staff)
   └─ Export morning plan HTML/PDF

3. POST-PLANNING (page11)
   ├─ Fill t_time_pairs (LiS times, customer times, breaks)
   ├─ Create t_work_assignments (non-project work)
   └─ Calculate hours worked

4. COST CALCULATION (Nachkalkulation)
   ├─ Personnel: t_time_pairs × t_employees.hourly_rate
   ├─ Materials: t_project_material_usage × t_material_prices
   ├─ Vehicles: t_project_vehicle_costs
   ├─ Services: t_project_service_usage/costs
   ├─ Revenue: t_project_revenue_items
   ├─ Calculate margins (transformers)
   └─ Export calculation report
